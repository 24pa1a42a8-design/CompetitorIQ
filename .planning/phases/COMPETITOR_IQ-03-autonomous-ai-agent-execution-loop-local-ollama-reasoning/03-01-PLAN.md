<task type="auto">
  <name>Task 1: Implement AgentToolRegistry and autonomous execution loop in agentService.js</name>
  <files>server/services/agentService.js</files>
  <read_first>server/services/agentService.js, server/services/strategicAnalysisService.js, server/repositories/competitorEventRepository.js</read_first>
  <action>
    1. Define `AgentToolRegistry` in `server/services/agentService.js` with 5 typed tools:
       - `search_events(params)`: Executes structured queries on `competitorEventRepository` with competitor filters, eventType, query keywords, date range, and organization isolation.
       - `get_competitor_comparison(params)`: Computes comparative momentum and event distribution between 2 or more competitors using `calculateCompetitiveMomentum` and event aggregation.
       - `correlate_strategic_patterns(params)`: Dispatches pattern recognition / connect-the-dots via `strategicAnalysisService.generateSingleAnalysis` or `connectTheDots`.
       - `analyze_pricing_signals(params)`: Extracts and compares pricing changes, tier structures, and currency amounts across competitors.
       - `recall_memory(params)`: Queries `hindsightService.recall` for semantic vector context with graceful credit degradation.
       Each tool must return a standardized contract: `{ tool, status: 'completed'|'degraded'|'failed', durationMs, itemCount, data, summary }`.

    2. Refactor the execution loop in `executeQuery` to:
       - Decompose user query into tool plan:
         - Compare queries (e.g. "Compare AWS and Oracle") → plans `get_competitor_comparison` + `search_events` + `recall_memory`.
         - Pricing queries (e.g. "What pricing changes happened?") → plans `analyze_pricing_signals` + `search_events`.
         - Pattern/strategy queries (e.g. "Connect dots on recent cloud moves") → plans `correlate_strategic_patterns` + `search_events` + `recall_memory`.
         - Specific or broad queries → plans `search_events` + `recall_memory`.
       - Execute planned tools sequentially or in parallel batches, recording rich tool execution steps into `executionSteps` with `toolName`, `durationMs`, `itemCount`, and `detail`.
       - Implement **Adaptive Query Relaxation (D-15)**:
         - If initial `search_events` with keyword filter returns 0 records for a recognized competitor, automatically execute a self-correction step (`self_correct_broaden_search`):
           - Broaden to competitor aliases (e.g. "GCP" → "Google Cloud").
           - Remove strict keyword filter to fetch recent competitor signals.
           - Record self-correction step in `executionSteps` with status `'self_corrected'`.
         - If still 0 events after relaxation, enforce strict fail-closed policy (D-09).
  </action>
  <verify>grep -n "AgentToolRegistry" server/services/agentService.js</verify>
  <acceptance_criteria>

    - `executionSteps` records detailed tool execution entries with `durationMs`, `itemCount`, and `tool`.
    - Adaptive query relaxation triggers and records self-correction when initial targeted query yields 0 results.
  </acceptance_criteria>
  <done>Tool registry and autonomous execution loop fully operational in agentService.js</done>
